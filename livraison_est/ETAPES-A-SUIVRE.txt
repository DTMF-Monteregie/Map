CARTE MONTÉRÉGIE-EST — ÉTAPES À SUIVRE
=======================================
trouvetaclinique.ca/monteregie-est/ — 20 août 2026


ÉTAPE 1 — Dézipper
--------------------
Dézippe ce fichier sur ton ordinateur. Tu obtiens 7 fichiers, dans la même
structure de dossiers que ton dépôt GitHub.

ATTENTION : le dossier « .github » commence par un point, donc il est CACHÉ par
défaut sur Mac et sur Windows.
  - Mac    : dans le Finder, appuie sur Cmd + Maj + . (point) pour l'afficher.
  - Windows: Explorateur → onglet Affichage → coche « Éléments masqués ».
Si tu n'arrives pas à le voir, ce n'est pas grave : voir l'étape 4, qui explique
comment le modifier directement sur GitHub sans passer par ce dossier.


ÉTAPE 2 — Déposer les fichiers de l'application
-------------------------------------------------
Sur GitHub, dans ton dépôt :
  a) Clique « Add file » → « Upload files ».
  b) Glisse-dépose ces éléments :
        index.html
        sw.js
        sitemap.xml
        le dossier  monteregie-est/   (avec son index.html à l'intérieur)
        le dossier  scripts/          (3 fichiers depuis le 21 août — le nouveau,
                                        app-pin-est.b64.txt, est utilisé par
                                        publier-monteregie-est.js, ne l'oublie pas)
        le dossier  assets/           (nouveau depuis le 21 août — bannière Est)
        manifest-est.webmanifest      (nouveau — app installable Montérégie-Est,
                                        voir section dédiée plus bas)
        icon-est-192.png
        icon-est-512.png
        icon-est-192-maskable.png
        icon-est-512-maskable.png
        apple-touch-icon-est.png
  c) GitHub va demander de confirmer le remplacement des fichiers existants
     portant le même nom : accepte.
  d) Message de commit suggéré :
        Carte dédiée Montérégie-Est
  e) Clique « Commit changes ».

ÉTAPE 4 — Mettre à jour le robot (la synchronisation automatique)
-------------------------------------------------------------------
Cette étape est ce qui garantit que tu n'auras JAMAIS à synchroniser les deux
cartes à la main. Sans elle, tout fonctionne quand même aujourd'hui, mais la
copie Montérégie-Est ne se mettra plus à jour toute seule si tu modifies le
design de l'application plus tard.

Le plus simple, directement sur GitHub (pas besoin du dossier caché) :
  a) Dans ton dépôt, ouvre le fichier :
        .github/workflows/generer-pages-seo.yml
     (tu peux y aller en collant ce chemin dans la barre d'adresse, après
      l'adresse de ton dépôt)
  b) Clique l'icône crayon (« Edit this file »).
  c) Sélectionne TOUT le contenu et supprime-le.
  d) Ouvre le fichier du même nom depuis le zip dans un éditeur de texte
     (Bloc-notes, TextEdit), copie tout, colle-le dans GitHub.
  e) Message de commit : « Robot : synchroniser aussi la carte Montérégie-Est »
  f) « Commit changes ».


ÉTAPE 5 — Confirmer que le robot a bien tourné
------------------------------------------------
Onglet « Actions » de ton dépôt. Une exécution « Régénérer les pages du site »
devrait apparaître (déclenchée par la modification de index.html) et se
terminer avec un crochet vert.

C'est normal qu'elle tourne : elle vérifie simplement que monteregie-est/
est à jour et que le sitemap est correct. Elle ne touche pas à data.json.

CE QUE TU DOIS SAVOIR POUR LA SUITE (2 choses seulement)
=====================================================================

1) MISE À JOUR DES DONNÉES — rien ne change pour toi
------------------------------------------------------
Quand tu reçois un formulaire et que tu modifies data.json, les DEUX cartes
se mettent à jour en même temps, automatiquement. Il n'y a rien à faire en
double, et il est impossible que les deux versions se désynchronisent : ce
n'est pas une copie des données, c'est le même fichier, lu par les deux
pages.

Testé pour de vrai pendant l'audit : j'ai ajouté une clinique de l'Est et
modifié une clinique existante dans data.json, sans toucher au moindre
fichier HTML. Résultat immédiat :
  - carte complète : 61 → 62 cliniques
  - carte Est      : 26 → 27 cliniques
  - la modification et la date de mise à jour visibles sur les deux
Les fiches détaillées (/cliniques/…) se régénèrent aussi toutes seules,
comme avant.

Autrement dit : ton processus de mise à jour ne change pas d'un iota.


2) LES ANNONCES — un petit mot à retenir
------------------------------------------
data.json contient UNE bannière d'annonce pour tout le site (« Prochaine
activité de recrutement »). Au moment de l'audit, elle annonçait le
« JR Express — RLS Jardins-Roussillon », donc une activité de la Montérégie-
OUEST. Sur la page dédiée, cette bannière aurait fait exactement ce que
Nancy ne veut pas.

Règle mise en place : sur la page Montérégie-Est, l'annonce s'affiche
UNIQUEMENT si tu l'as explicitement marquée comme étant de l'Est.

  - Annonce concernant la Montérégie-Est → ajoute "region": "Est" :

        "annonce": {
          "titre": "Prochaine activité de recrutement",
          "texte": "Tournée des GMF de Saint-Hyacinthe…",
          "region": "Est",
          "dateFin": "2026-10-15"
        }

    → visible sur les DEUX cartes.

  - Annonce concernant un autre territoire (ou générale) → ne mets rien :

        "annonce": { "titre": "…", "texte": "…", "dateFin": "…" }

    → visible seulement sur la carte complète, jamais sur la page Est.

C'est le seul point où tu dois avoir une pensée pour les deux versions.
En cas d'oubli, l'erreur va dans le bon sens : l'annonce est masquée sur la
page Est plutôt que d'y apparaître par erreur.

   Le lien « Liste des cliniques » (qui menait au répertoire des trois

4) COULEURS D'ÉPINGLES PAR RLS SUR LA CARTE EST
   Sur la page Montérégie-Est, les épingles (et les pastilles numérotées
   de la liste) sont colorées par RLS, avec la légende « Réseau local
   (RLS) » en bas à gauche — exactement comme sur la toute première
   carte cisssme.github.io/Map/ :

       Richelieu-Yamaska  vert        #15803d   (11 milieux)
       Pierre-De Saurel   bleu marine #2f4a7a   (3 milieux)

   Ces trois codes ont été relevés par échantillonnage des pixels de ta
   capture d'écran, pas estimés à l'œil. Détail amusant : ils étaient
   déjà dans ton index.html sans plus servir à rien — ce sont les
   couleurs des trois épingles de l'écran de chargement (.pin-rose,
   .pin-green, .pin-blue). L'écran de chargement était le dernier
   vestige de ce code de couleurs; il redevient cohérent avec la carte.

   La carte des trois territoires est STRICTEMENT inchangée : ses
   épingles restent colorées par territoire (26 roses, 20 vertes,
   15 bleues) et sa légende reste celle des régions. Vérifié en comptant
   les couleurs réellement affichées sur les deux cartes.

5) ORDRE DE LA LISTE SUR LA CARTE EST
   La liste est maintenant regroupée par RLS, dans l'ordre de la légende :
       1 à 12   Pierre-Boucher     (rose)
       13 à 23  Richelieu-Yamaska  (vert)
       24 à 26  Pierre-De Saurel   (bleu marine)
   Auparavant, le premier critère de tri était le TERRITOIRE — ce qui
   regroupe bien les couleurs sur la carte des trois territoires, mais
   ne servait à rien sur la carte Est où tout est « Est ». La liste

   s'alternaient au fil de la numérotation.
   À l'intérieur de chaque RLS, l'ordre reste le même qu'avant :
   GMF-U, puis GMF-R, puis les GMF, puis les CLSC, par ordre

   La carte des trois territoires garde exactement son tri d'origine
   (vérifié : elle commence toujours par Jardins-Roussillon).

AJOUT DU 21 AOÛT (suite) — la carte Montérégie-Est s'installe comme
une application DISTINCTE de la carte principale
=====================================================================

CE QUI CHANGE
   Avant, installer « l'application » depuis n'importe quelle page
   (carte complète ou carte Est) installait la MÊME app, avec la même
   icône bleue, et l'ouvrait toujours sur la carte des trois
   territoires. Ce n'était pas correct pour quelqu'un qui n'utilise
   que la carte Est.
   Maintenant, un utilisateur peut avoir sur son téléphone DEUX
   applications séparées, avec chacune sa propre icône, son propre nom
   sous l'icône, et qui s'ouvre directement sur la bonne carte :
     - « Trouve ta clinique » (icône point bleu) → carte des trois
       territoires;
     - « Montérégie-Est » (icône point ROSE) → carte Montérégie-Est.
   Les DEUX continuent de lire les mêmes données (data.json) : aucun
   risque de désynchronisation, exactement comme pour le reste du
   site.

CE QUI A ÉTÉ AJOUTÉ
   - manifest-est.webmanifest (à la racine, à côté de manifest.json) :
     le fichier qui dit à Android/Chrome « ceci est une application
     séparée, qui s'appelle Montérégie-Est, qui s'ouvre sur
     /monteregie-est/, avec ces icônes-là ». Le manifeste de la carte
     principale (manifest.json) n'a pas été touché.
   - icon-est-192.png, icon-est-512.png, icon-est-192-maskable.png,
     icon-est-512-maskable.png, apple-touch-icon-est.png : le même
     logo, mais avec le petit point recoloré en rose (#ff3d96) — même
     méthode que pour le logo de l'écran de chargement (point isolé
     du reste du dégradé, pas un filtre global). Les icônes de la
     carte principale (icon-192.png, etc.) sont inchangées.
   - Sur la page Montérégie-Est seulement : le lien vers le manifeste,
     l'icône iOS et le nom sous l'icône iOS pointent vers ces nouveaux
     fichiers plutôt que ceux de la carte principale. Le bouton
     « ⤓ Installer » affiche « Installer la carte Montérégie-Est » au
     lieu de « Installer l'application ».
   - sw.js (le service worker) met maintenant aussi en cache le
     nouveau manifeste et les nouvelles icônes, pour que l'app Est
     reste installable même hors ligne. J'ai gardé UN SEUL service
     worker, comme demandé : rien n'a été dupliqué, seule sa liste de
     fichiers à mettre en cache s'est allongée. Numéro de cache monté
     à v30 (purge automatique de l'ancien cache au prochain
     chargement, comme à chaque changement de ce fichier).

CE QUI N'A PAS CHANGÉ
   - Le bouton d'installation ne peut PAS installer la mauvaise app :
     le navigateur installe toujours le manifeste lié à la page où on
     clique, donc jamais la carte principale par erreur depuis
     /monteregie-est/. Aucune logique supplémentaire n'était
     nécessaire pour ça, c'est le comportement standard du navigateur.
   - Aucun lien vers les autres territoires n'apparaît dans
     l'expérience Est installée : c'était déjà vrai (voir les ajouts
     du 20 et du 21 août plus haut) et rien n'y a été touché.
   - Les favoris/notes enregistrés localement, le mode sombre, et tout
     le reste du fonctionnement de l'app restent identiques dans les
     deux versions installées.

COMMENT VÉRIFIER APRÈS LE DÉPÔT
   1. Ouvre https://trouvetaclinique.ca/monteregie-est/ dans Chrome
      (Android ou ordinateur). Un bouton d'installation devrait
      apparaître avec le texte « Installer la carte Montérégie-Est ».
      Installe-la : l'icône qui apparaît doit avoir le point ROSE, et
      l'app doit s'ouvrir directement sur la carte Est.
   2. Ouvre https://trouvetaclinique.ca/ et installe aussi cette
      version : tu dois maintenant avoir DEUX icônes distinctes sur
      ton téléphone, avec deux noms différents.
   3. Sur iPhone/iPad (Safari) : depuis /monteregie-est/, bouton
      Partager → « Sur l'écran d'accueil ». Le nom proposé doit être
      « Montérégie-Est » et l'icône doit avoir le point rose.
   4. Optionnel mais recommandé : dans Chrome sur ordinateur, ouvre
      les Outils de développement (F12) → onglet Application →
      Manifest, sur les deux pages, pour confirmer que chacune lit le
      bon fichier (manifest.json vs manifest-est.webmanifest) sans
      erreur. Si Chrome signale une erreur de type MIME sur
      manifest-est.webmanifest (ça arrive parfois selon la
      configuration exacte d'un hébergeur), dis-le-moi : je le
      renommerai en manifest-est.json (même contenu), comme
      manifest.json qui, lui, fonctionne déjà chez toi.
